# Contributing to Open LLM Engineering

Thank you for your interest in contributing.

## How to contribute

1. Fork the repository.
2. Create a dedicated feature or fix branch.
3. Make your changes.
4. Add or update tests where appropriate.
5. Run the test suite locally.
6. Keep documentation synchronized with code changes.
7. Open a pull request with a clear summary and validation steps.

## Development workflow

Use descriptive branch names, for example:

- `feature/kv-cache`
- `feature/lora`
- `fix/checkpoint-loading`
- `docs/improve-inference-guide`

## Pull request requirements

Each pull request should include:

- A clear description of the change
- The related issue, if applicable
- Tests for new or modified behavior
- Documentation updates where needed
- Benchmark results for performance-sensitive changes

## Code quality

Contributions should:

- Follow the existing project structure
- Avoid unnecessary dependencies
- Keep changes focused and reviewable
- Preserve attribution and applicable licensing
- Pass automated checks before merge

## Security

Do not publicly disclose suspected vulnerabilities.

Please use the repository's private security reporting process for security-sensitive issues.

## Issue labels

Issues may be organized using labels such as:

- `bug`
- `enhancement`
- `documentation`
- `security`
- `performance`
- `good first issue`
- `help wanted`
